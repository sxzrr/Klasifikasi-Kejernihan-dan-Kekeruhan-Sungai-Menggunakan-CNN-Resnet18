1️⃣  XCEPTION (INITIAL APPROACH - TensorFlow/Keras)
═══════════════════════════════════════════════════════════════════════════════

🏗️ ARCHITECTURE OVERVIEW:
──────────────────────────────────────────────────────────────────────────────

    Xception = "Extreme Inception"
    └─ Depthwise Separable Convolutions (more efficient than regular conv)

    Architecture Flow:
    Entry Flow (3 blocks) → Middle Flow (8 blocks) → Exit Flow (2 blocks)
    ├─ Input: (224, 224, 3) images
    ├─ Progressive feature extraction
    └─ Output: 2048 features → Binary classification

📊 SPECIFICATIONS:
──────────────────────────────────────────────────────────────────────────────

    Parameter Count:    20.9 Million parameters
    Model Size:         ~80 MB (float32)
    Architecture:       Depthwise separable convolutions
    Pre-training:       ImageNet (1000 classes)
    Implementation:     TensorFlow 2.10 / Keras
    
    Architecture Components:
    ├─ Entry Flow:      3 convolution blocks
    ├─ Middle Flow:     8 depthwise separable blocks (repeated)
    ├─ Exit Flow:       2 final blocks
    └─ Custom Head:     Dense(256) → ReLU → Dropout(0.5) → Dense(2)

⚙️ WORKING PRINCIPLE (Depthwise Separable Convolution):
──────────────────────────────────────────────────────────────────────────────

    Standard Convolution (3×3×256 filters):
    ├─ Input: H × W × C_in
    ├─ Output: H × W × C_out
    ├─ Parameters: 3 × 3 × C_in × C_out (HUGE!)
    └─ Example: 3×3×512×1024 = 4,718,592 parameters per layer

    Depthwise Separable Convolution (Xception approach):
    ├─ Step 1: Depthwise Conv (3×3 per channel)
    │          Parameters: 3 × 3 × C_in = 2,304
    │
    ├─ Step 2: Pointwise Conv (1×1 for cross-channel mixing)
    │          Parameters: 1 × 1 × C_in × C_out = 524,288
    │
    ├─ Total: 2,304 + 524,288 = 526,592 (11x FEWER!)
    └─ Efficiency: 526,592 / 4,718,592 ≈ 0.11 (much more efficient)

💡 WHY XCEPTION WAS CHOSEN (Initially):
──────────────────────────────────────────────────────────────────────────────

    ✓ ADVANTAGES:
    ├─ Efficient architecture → fewer parameters (20.9M)
    ├─ Faster training → depthwise separable convolutions
    ├─ Lower memory → ideal untuk resource-limited scenarios
    ├─ Good accuracy → proven on ImageNet
    └─ Fine-tuning friendly → transfer learning ready

    ✗ DISADVANTAGES:
    ├─ TensorFlow/Keras built on TensorFlow
    ├─ Windows GPU support problematic (no pip binary with CUDA)
    ├─ Training VERY SLOW on CPU (~6-7 hours)
    └─ Overfitting: Achieved 80.65% on test set

❌ TRAINING RESULTS (CPU - 6+ hours):
──────────────────────────────────────────────────────────────────────────────

    After 6-7 hours CPU training:
    ├─ Training Accuracy: ~92%
    ├─ Validation Accuracy: ~85%
    ├─ Test Accuracy: 80.65%
    ├─ Time: 6-7 hours ⏱️ TOO SLOW
    └─ Status: ABANDONED (switched to PyTorch + ResNet18)

⚠️ WHY XCEPTION WAS ABANDONED:
──────────────────────────────────────────────────────────────────────────────

    1. GPU Support Issue
       ├─ TensorFlow pip binary untuk Windows tidak include CUDA
       ├─ Training harus di CPU → extremely slow
       └─ 6+ hours untuk 1 model training = not practical

    2. Depthwise Separable Limitation
       ├─ While efficient, still memory-intensive untuk full fine-tuning
       └─ No advantage jika GPU tidak bisa digunakan

    3. Development Friction
       ├─ Debugging slow
       ├─ Iterasi cepat tidak possible
       └─ Team productivity: 0

2️⃣  RESNET18 (CURRENT APPROACH - PyTorch)
═══════════════════════════════════════════════════════════════════════════════

🏗️ ARCHITECTURE OVERVIEW:
──────────────────────────────────────────────────────────────────────────────

    ResNet18 = "Residual Network with 18 layers"
    └─ Skip connections (residual blocks) prevent vanishing gradients

    Architecture Flow:
    Conv1 → Layer1 → Layer2 → Layer3 → Layer4 → AvgPool → FC → Softmax
    ├─ Input: (224, 224, 3) images
    ├─ 4 residual layers (Layer1-4)
    ├─ Skip connections throughout
    └─ Output: 512 features → Binary classification

📊 SPECIFICATIONS:
──────────────────────────────────────────────────────────────────────────────

    Parameter Count:    11.2 Million parameters (vs Xception 20.9M)
    Model Size:         ~45 MB (float32)
    Architecture:       Residual blocks dengan skip connections
    Pre-training:       ImageNet (1000 classes)
    Implementation:     PyTorch 2.7.1
    GPU Support:        ✓ CUDA 11.8 (works perfectly on Windows!)
    
    Architecture Components:
    ├─ Conv1:           Initial 7×7 convolution
    ├─ Layer1:          2 residual blocks (64 channels)
    ├─ Layer2:          2 residual blocks (128 channels)
    ├─ Layer3:          2 residual blocks (256 channels)
    ├─ Layer4:          2 residual blocks (512 channels)
    ├─ AvgPool:         Global average pooling
    └─ Custom Head:     Linear(512→256) → ReLU → Dropout(0.5) → Linear(256→2)

⚙️ WORKING PRINCIPLE (Residual Blocks & Skip Connections):
──────────────────────────────────────────────────────────────────────────────

    Standard Deep Network Problem:
    ├─ Deeper networks → harder to train
    ├─ Vanishing gradient problem
    └─ Accuracy actually decreases with more layers!

    Residual Block Solution (Skip Connection):
    
    Traditional Path:
    ─────────────────────────────
    Input → Conv → ReLU → Conv → Output
    
    Residual Path (ResNet):
    ─────────────────────────────────────
    Input → [Conv → ReLU → Conv] → Output
      └─────────────────┬────────────────┘
                        └─ ADD INPUT BACK TO OUTPUT
    
    Mathematical:
    ├─ Traditional: y = F(x)  (direct mapping)
    ├─ Residual:    y = F(x) + x  (learn residual, not full mapping)
    └─ Effect: Easier gradient flow → train deeper networks!

💡 WHY RESNET18 WAS CHOSEN (Current):
──────────────────────────────────────────────────────────────────────────────

    ✓ ADVANTAGES:
    ├─ Lightweight → 11.2M parameters (vs Xception 20.9M)
    ├─ Fewer layers → Less overfitting risk
    ├─ PyTorch support → EXCELLENT Windows GPU support
    ├─ Fast training → 25 minutes GPU (vs 6+ hours CPU Xception)
    ├─ Easy fine-tuning → Transfer learning friendly
    ├─ Good accuracy → Proven on ImageNet
    └─ Production ready → Simple, stable, reliable

    ✗ DISADVANTAGES:
    ├─ 18 layers might be "deeper" than needed for 204 images
    ├─ Overfitting possible dengan small dataset (mitigated dengan regularization)
    └─ None significant for this project!

✅ TRAINING RESULTS (GPU - 25 minutes):
──────────────────────────────────────────────────────────────────────────────

    Stage 1 (Frozen backbone, 5 epochs):
    ├─ Training Accuracy: 86.6%
    ├─ Validation Accuracy: 77.4%
    └─ Time: 3 minutes
    
    Stage 2 (Fine-tuning, 20 epochs):
    ├─ Training Accuracy: 100%
    ├─ Validation Accuracy: 93.5%
    ├─ Time: 22 minutes
    └─ Total: ~25 minutes ⏱️ VERY FAST!
    
    Test Results:
    ├─ Test Accuracy: 83.9%
    ├─ ROC-AUC: 0.846
    └─ Status: PRODUCTION READY ✓

5️⃣ ARCHITECTURAL COMPARISON: DEPTHWISE SEP. vs RESIDUAL BLOCKS
═══════════════════════════════════════════════════════════════════════════════

XCEPTION: Depthwise Separable Convolutions
──────────────────────────────────────────────────────────────────────────────

    Advantage: Parameter Efficiency
    ├─ Separates spatial filtering (depthwise) from feature mixing (pointwise)
    ├─ 3×3×C_in + 1×1×C_in×C_out < 3×3×C_in×C_out
    └─ Result: ~90% fewer parameters for similar receptive field

    Challenge: Still needs GPU for speed
    ├─ Windows GPU support issue with TensorFlow
    └─ Results in CPU training (ultra slow)

RESNET18: Residual Skip Connections
──────────────────────────────────────────────────────────────────────────────

    Advantage: Better Gradient Flow
    ├─ Skip connections help gradients flow through deep networks
    ├─ y = F(x) + x (easier to learn than y = F(x))
    └─ Result: Can train deeper networks without vanishing gradients

    Challenge: More total parameters
    ├─ But still lightweight (11.2M for ResNet18 vs 20.9M for Xception)
    └─ GPU training compensates (14x faster)

Which is Better?
├─ For Resource-Constrained: Xception (if GPU available)
├─ For Windows GPU Development: ResNet18 ✓ WINNER
├─ For Production: ResNet18 (simpler, faster, proven)
└─ For Research: Either (depends on project needs)

6️⃣ WHY RESNET18 IS THE RIGHT CHOICE FOR THIS PROJECT
═══════════════════════════════════════════════════════════════════════════════

✅ REASONS:

1. GPU Support on Windows
   ├─ PyTorch pip binaries include CUDA support
   ├─ TensorFlow Windows pip doesn't
   └─ This alone makes it 14x faster

2. Lightweight Architecture
   ├─ 11.2M parameters vs 20.9M (Xception)
   ├─ Less prone to overfitting dengan 204 images
   └─ Faster inference

3. Research & Development
   ├─ PyTorch is more flexible untuk experimentation
   ├─ Easier to implement custom regularization (early stopping, weight decay)
   └─ Better for iterative improvements

4. Production Deployment
   ├─ PyTorch model is simpler to export & deploy
   ├─ Better support untuk edge devices
   └─ More tools & frameworks support PyTorch

5. Community & Support
   ├─ PyTorch ResNet18 = most common computer vision starter
   ├─ Tons of examples + documentation online
   └─ Easy to get help if stuck

7️⃣ COULD WE HAVE USED SOMETHING LIGHTER?
═══════════════════════════════════════════════════════════════════════════════

Alternative Architectures for Small Dataset:

1. MobileNetV2 (3.5M parameters)
   ├─ Even more efficient than Xception
   ├─ Depthwise separable convolutions + inverted residuals
   ├─ Designed for mobile devices
   └─ Would be EXCELLENT for 204 images
   
2. SqueezeNet (1.2M parameters)
   ├─ Very lightweight
   ├─ Fire modules (compress → expand)
   └─ But more experimental

3. ResNet18 (11.2M) ✓ CURRENT
   ├─ Balanced: lightweight enough, not too small
   ├─ Well-documented, stable, proven
   └─ Good choice for this project

Why We Didn't Use MobileNetV2?
├─ ResNet18 was already working well
├─ MobileNetV2 similar performance, maybe slightly better
├─ Would need retrain (time cost)
└─ Current ResNet18 is "good enough" ✓

Could We Switch to MobileNetV2?
├─ YES, easily (same PyTorch framework)
├─ Would reduce overfitting slightly more
├─ Training would be marginally faster
├─ But improvement: +1-2% accuracy at best
└─ DECISION: Not worth the retrain time now
